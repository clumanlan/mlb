Two systematic failure modes, not just noise

UNDER-prediction

Cold-start pitchers who turn out to go deep

The 0–2-starts-this-season bucket is the single worst segment in the whole val set: MAE 3.246 vs. 2.578 for pitchers with 11+ starts, with a systematic +0.694 under-prediction bias (n=970). Worked examples: pitchers with starts_n=0 and last_season_avg=NaN (no starts last season either — true blanks) go on to throw 6–9 efficient innings, 20–25 batters faced, while the cascade’s expected_batters_faced_weight sits near 0 and it falls back to a generic team/league average that undershoots by 9–14 batters.

OVER-prediction

Established starters pulled early — but not because they got hit

The worst 25 over-predictions are almost all established starters (starts_n 10–32, cascade confidence weight 0.4–0.86 — the model was sure) who left after 0–2 IP. The tell: h/r/er are mostly 0–2, not a blowup line — this is the signature of an in-game injury exit, rain delay, or a planned short/piggyback outing, not poor performance the model could see coming from a bad recent line. Nothing in the current feature set carries recent-start trend — only season-to-date averages, which react slowly.

Candidate features, in priority order

1

Trailing-3-start PA/start trend zero new code path

Directly targets the over-prediction pattern (recent workload dipping before an established pitcher gets pulled early). game_context.build_pitcher_start_pa_this_season(pbp, window=3) is already generalized to accept a trailing-N-start window — this pipeline currently only calls it with the default window='season'. Pair the two outputs with interaction_feats.find_rolling_trend_pairs / build_trend_features for a ratio + hot/cold direction signal — the exact recipe short_outing_predictor's v1 already validated for a closely related target (trailing-3-start IP trend).

2

Pitcher's own rest days, not team rest days needs new function

pitcher_team_days_since_last_game measures the team's rest (almost always 1 — teams play daily), not the starter's own days since his last start (normally 4–5 on a regular rotation). No build_pitcher_rest_days equivalent exists yet in game_context.py — would need building (real rotation slot / short-rest / extra-rest-after-IL signal), via impl-planning + TDD.

3

Multi-season lookback for the true cold-start rows needs investigation

For rows where pitcher_last_season_start_pa_avg_pa_per_start is NaN (no starts at all last season — injury or rookie), the cascade falls straight to team/league average. Extending season_stats.build_pitcher_start_pa_stats to fall back to the most recent season with starts (not strictly "last season") could recover real signal for returning-from-injury pitchers specifically — needs checking whether that materially differs from true rookies before committing to it.
