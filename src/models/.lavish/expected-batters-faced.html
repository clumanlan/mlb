02

Why a threshold lock didn't fit

The natural next move looked like n_pa_predictor's playbook — sweep a confidence threshold, lock an operating point. That playbook assumes a binary target. k_predictor's real target isn't: a DK strikeout prop is a count compared against a line that moves game to game. Summing per-PA probabilities via 1 − ∏(1−p) only ever answers "at least one," at batter grain — not "how many, for this pitcher, across the whole start."

Closing that gap needs two things a confidence threshold doesn't provide: an estimate of how many batters this pitcher will face, and a way to turn per-PA probabilities into a full distribution over the total. This diff is the first piece.

03

The cascade

Same shrinkage shape this codebase already trusts — build_expected_start_innings, and before that the hit_predictor baseline that beat every gradient-boosted model tried. Closed-form, not another trained classifier. The one addition: a team-level rung between the pitcher's own thin sample and the league floor.

1 · pitcher
Own last-season avg PA/start
2 · team
Current team's weighted avg
3 · league
League-wide weighted avg
blend
shrunk toward this season's own emerging average, weight = starts_n / (starts_n + k)
Why team ranks above league, not instead of it

A team's own quick-hook-vs-let-them-go-deep tendency is real, but a rotation is ~5–8 arms a season against the league's ~150 — noisier, and partly just "who's on the roster" rather than pure philosophy. League stays the final floor precisely because it's the more stable one; team fills the gap above it rather than replacing it.

04

What didn't change

The obvious shortcut — retrofit the existing build_expected_start_innings with a team rung, or rename it for clarity now that a sibling exists — was rejected. That function isn't a clean edit site anymore; it's load-bearing.

Depends on the current behavior, unchanged
  • n_pa_predictor — the one locked production artifact in this repo (XGBoost @ 0.85 confidence, 64.7% precision) uses it as the opposing-starter feature
  • short_outing_predictor — baseline and v1 use it directly for the pitcher's own start
  • 8+ files total, several frozen experiment snapshots (v4, v5) this project treats as historical record

A same-values rename still touches every one of those. A behavior change means re-verifying the locked threshold. Neither cost was worth paying for naming symmetry — a cross-reference docstring on the old function does the same job for a reader, for free.
