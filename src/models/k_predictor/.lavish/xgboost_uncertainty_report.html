What does this model's uncertainty actually look like?

Every prediction below comes from the same pipeline: v6's tuned XGBoost (max_depth=2, learning_rate=0.03, fit on 2018/2019/2022 with early stopping against 2023, best_iteration 445) scores each synthetic batter-slot in a 2024 start, and an exact Poisson-binomial combinator turns those N per-slot probabilities into a full predicted distribution over that start's total strikeouts — not just a point estimate. This report walks that distribution from aggregate honesty, down through whether its width means anything, down to ten real 2024 starts.

What "P(K>5.5) discrimination" means: for each start, sum the predicted distribution's probability mass above 5.5 K — a stand-in for a DK over/under line — to get one number, P(total K > 5.5). ROC-AUC then asks: across all 4,786 starts, how well does that single number rank the starts that actually went over against the ones that didn't? 0.5 = no better than a coin flip, 1.0 = perfect ranking. 0.690 means real, moderate discrimination — worse than a perfect model, clearly better than guessing. This is a different question from v6's own game-grain "1+ strikeout" check (ROC-AUC 0.624) reported elsewhere — that one asks "will this batter-game have a K at all," this one asks "will this pitcher's whole game go over a specific line" — don't read them as the same number measured twice.

Read this as: in aggregate, the predicted distribution's width is trustworthy — if you said "80% chance the real K total lands in this band" over and over across 4,786 starts, you'd be right about 80% of the time. That's a real, checkable property, not a hand-wave. What it does not tell you is whether the width is doing anything useful per start — that's Section 2.

2. Does the interval width warn you which starts are risky?

Aggregate coverage being honest doesn't mean a wide predicted interval means anything for one specific start. This is the question in between — the population this report's examples are drawn from, plotted whole, so the examples in Section 3 read as real points in a real distribution rather than handpicked outliers.

Predicted mean K (x-axis) barely moves — it clusters in a narrow 3–8 band for nearly every start, colored by sample-size quartile with no visible separation. Realized K (y-axis) spans 0–15. The point estimate is a soft consensus; the outcome is not.

corr = 0.07. The 80% interval width is almost always 4–6 strikeouts wide, regardless of start. At that most-common width of 5, residuals still range from 0 to over 9. A wide band here doesn't flag a riskier start — the width barely varies at all, so it can't.

The residual distribution isn't symmetric noise: the left tail (predicted < realized, i.e. under-prediction) stretches to −10, while the right tail (over-prediction) barely passes +6. Big misses are lopsided in one direction — see why in Section 3.

The gap between Section 1 and Section 2: the model is honest on average about how wide its uncertainty should be, but that width is close to a constant — it isn't a per-start risk signal. If you're using this to size a bet, "narrow interval" and "wide interval" carry almost no information about which nights are the dangerous ones.

Every one of the 5 worst starts is a massive under-prediction on an unusually dominant outing (11–14 realized K against predicted means of 2.7–5.3), and every realized K falls outside even the 80% band — not by a little. This isn't five unrelated bad-luck rows; it's one structural gap. The predicted distribution comes from combining independent per-slot probabilities (each slot ≈20–25% chance of a K), and independent combination has thin tails by construction — it cannot generate the kind of correlated, all-game dominance a real "he's got it tonight" start produces. No pre-game feature in this pipeline signals that in advance, and the interval doesn't widen to compensate (Section 2).

4. Is this structural, or specific to XGBoost?

Section 2 found the interval width barely tracks real risk. Section 3 found the worst misses are all dominant, correlated starts the model can't foresee. Both could plausibly be fixed by a richer per-slot model — or both could be a property of combining independent per-slot probabilities at all, regardless of how good the per-slot score is. To find out, the exact same pipeline (cascade → slot expansion → Poisson-binomial → coverage check) was re-run with one change: the per-slot score is replaced with just the batter's own strikeout rate, shrunk from last season toward this season's emerging rate — no pitcher, no matchup, no game context at all.

"Threshold ROC-AUC" is the same P(K>5.5)-ranks-starts-correctly check explained in Section 1 — here it drops from 0.690 to 0.594 once the pitcher is removed, which is exactly the kind of real, model-specific value XGBoost's features add (see left card above).

What XGBoost's features are actually buying

MAE, coverage honesty, and discrimination on the over/under threshold all get measurably worse once the pitcher is dropped entirely — expected, since pitcher stuff is a big share of what determines strikeouts. This part is real, model-specific value, not noise.

What richer features do not fix

corr(interval width, error) doesn't improve with more features — it gets worse (0.034 vs. 0.071). A 42-feature model's uncertainty band is no more informative about which start is dangerous than a model that only knows one batter-level rate.

The clearest evidence is the worst-5 list itself: 3 of the naive model's 5 worst misses are the exact same real starts as XGBoost's — Pablo López, Luis Gil, and Spencer Arrighetti all blow up both models, and the two new names that round out the naive list (Blake Snell, 15 realized K; Tyler Glasnow) are cut from the same cloth. A model that knows nothing about the pitcher fails on the same nights as a 42-feature model that knows a great deal about the pitcher. That's the strongest available signal that the "can't see a historic dominant start coming" limitation is architectural — independent-slot combination has thin tails by construction — not a gap in XGBoost's feature set.

So what does this mean for a production decision?

  • The aggregate uncertainty is honest and checkable — the 80% band covers ~80% of real outcomes, flat across sample-size quartiles. That's not a rounding trick; it held up identically when this same check was run against v2's LR.
  • The interval width is not a per-start risk signal (corr = 0.07 with actual error, and it gets worse, not better, with a richer model). It can't currently tell you which specific start is about to blow the model up.
  • The failure mode that matters is narrow and specific: unusually dominant starts, always under-predicted, always outside the band. Section 4 confirms this is architectural (independent-slot combination has thin tails), not a feature gap — a model with zero pitcher signal fails on the same real starts as the 42-feature XGBoost model.
  • For a betting application, this is exactly the scenario where the model will look calibrated in aggregate while being confidently wrong on the highest-value over/blowout nights — and more features alone won't close that gap.
